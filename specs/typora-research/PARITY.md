# “Typora 体验一致”的可验收边界

状态：验收设计，尚无运行对照结果。输入样例见 [fixtures/editor-behavior.md](fixtures/editor-behavior.md)，操作记录结构见 [fixtures/behavior-cases.json](fixtures/behavior-cases.json)。当前所有 observed_result 为 null。

## 1. 一致性按行为验证

原生实现可以复现用户可见行为，不必复制 DOM、内部模块号或 JS bridge。静态反编译不能证明视觉、输入法、性能或所有历史版本都一致；“完全一致”必须指一组版本固定、场景明确、结果可比较的行为。

基准对象应是经过签名和来源核验的官方 Typora 包。当前副本仅供静态定位，其 Authority 为 Antibiotics；不要把该副本直接当作正式 oracle。

| 层次 | 验收对象 | 成功判据 |
|---|---|---|
| 文件一致性 | 原始 Markdown、附件引用、frontmatter、换行 | 无编辑时字节一致；实际编辑时变更只落在对应的原文范围 |
| 编辑一致性 | 输入规则、块转换、标记展开、选区、撤销 | 同一输入序列得到约定的正文、结构、选区与历史 |
| 视觉一致性 | 字体、行距、标记显隐、表格/块布局、焦点 | 同字体、尺寸、缩放和主题下逐场景比较；截图只证明该帧 |
| 系统一致性 | IME、辅助功能、剪贴板、系统菜单、文件变更 | 遵循 AppKit 行为，无候选中断、owner 串写或不可恢复操作 |
| 渲染一致性 | 代码、公式、图表、HTML | 渲染稳定、错误可编辑、离线行为明确；逐语言/语法建立覆盖 |
| 导出一致性 | HTML、PNG/SVG、PDF、可选 Pandoc | 无缺字裁切；文本、链接、目录可用；取消和失败终态正确 |
| 性能一致性 | 固定样例和硬件下的输入/解析/渲染延迟 | 建立实测预算；不以“原生”或“没有 JS”替代测量 |

本轮得到的调用路径和字段可以支撑文件/编辑/导出设计；其余栏位都需要运行结果。

## 2. 必须冻结的对照条件

每次运行记录：应用路径和 SHA-256、官方签名核验结论、版本/build、macOS 版本、机器型号、字体、主题、字号、缩放、窗口尺寸、locale、键盘布局、输入法及其配置。自编 Markdown 样例也记录 SHA-256。

每个场景至少保留：

1. 初始 Markdown 和初始选区。
2. 逐步输入/点击/菜单动作；输入法场景不能以直接插入最终中文字符串代替组合输入。
3. 每个有意义阶段的源文本、渲染状态、选区、焦点与 undo/redo 结果。
4. 需要视觉比较时的截图；图表错误和资源未就绪状态也记录。
5. 输出文件的实际检查结果，而不只记录“文件存在”或工具自报成功。

没有观测结果的条目保持 `not-run`；证据不完整时标 `partial`，不能自动升为 pass。

## 3. 输入与编辑验收

第一组至少覆盖：

- 拼音、候选取消、候选确认、连续组合更新；段落、表格、代码块三种位置。
- 组合重音、代理对、family emoji；UTF-16/UTF-8/grapheme 坐标不能互相代用。
- 块首/块尾 Enter、Backspace、Delete，跨块选取和替换。
- 列表续项、空项退出、嵌套、任务状态切换，quote 内列表。
- 行内强调/链接/代码的标记展开与收回；显示范围和原文范围的映射。
- 表格导航、末格、新行、移动列、跨单元格粘贴、含 pipe/换行的内容。
- 代码/数学/图表源态与渲染态进入/退出，错误渲染仍可编辑。
- 连续输入聚合、选区移动分组、格式/拆块/表格事务、新编辑清 redo 分支。
- 源码/渲染模式切换后文本、选区、滚动和 undo 的定义明确。

待补测的具体键盘规则不得凭经验写为 Typora 的实际行为。即使采用更稳健的 AppKit 规则，也要标为 Mdown 设计选择。

## 4. 文档与原文往返验收

原始 Markdown 是持久化权威内容；禁止把 HTML round-trip 当作常规保存方式。

- 无编辑打开/关闭/模式切换必须无字节漂移。
- 未变更范围保留原始定界符、空白、列表编号、换行和注释；格式清理必须由显式命令触发。
- CRLF、末尾换行、frontmatter 和脚注/引用定义分别验证；使用固定的 `roundtrip-crlf.md` 与 `roundtrip-no-final-newline.md`，按 fixtures/manifest.json 的字节摘要对照。
- 文档 A 的缓冲、撤销、渲染回调和附件操作不能发布到文档 B。
- 当前未保存修改与外部文件修改相遇时，不能静默覆盖任意一侧。
- 版本备份和编辑会话恢复分别验证；撤销历史是否跨重启保留属于独立产品决策。

Typora 的原生快照字段说明需要保存这些状态；不代表 Mdown 应使用同样的序列化格式或同样的内部 history 结构。

## 5. 导出验收

从 immutable snapshot 导出，记录 noteID、revision、导出配置和 renderer 版本。等待资源的结果必须显式区分 ready、failed、timeout、cancelled；超时不应悄悄把未完成图片当成功。

| 格式 | 必查项 |
|---|---|
| HTML | 源/渲染态不混入编辑 UI；样式策略明确；附件路径与离线资源完整 |
| 单块 SVG/PNG | 完整视口、文字和尺寸；只包含选中块；长/宽图、错误图和透明背景 |
| 整文档图片 | 长文分段/最大尺寸策略；不能因位图大小限制截断 |
| PDF | 中文/emoji、搜索与复制、字体映射、内部/外部链接、outline、页码/总页数、页边距和分页 |
| Pandoc | 可选依赖检测、argument array、并行读取 stdout/stderr、退出码、取消和写入失败 |

现有“Mermaid 单张保存优先”的 D 线仍可独立交付；全编辑器替换不能成为单图导出的前置阻碍。

## 6. 性能与零 JS 门槛

建议先定义两个不同完成点：

1. **编辑链路本地化：**正文、选择、输入规则、undo、源/渲染切换、保存均不依赖 JavaScript；现有图表/公式 renderer 可在异步、无编辑权的边界内工作。
2. **全部渲染本地化：**高亮、公式、Mermaid/PlantUML、演示、HTML 和导出等剩余 JS 分别有原生替代，逐项达到兼容和视觉门槛后再移除相应资源。

第一点不是“整应用零 JS”。第二点不能通过仅删除 bundled scripts 宣称完成。

性能采用固定 1 MB/10 MB 样例与块密集场景，分别记录打开、首帧、键入、撤销、模式切换、导出时间和峰值内存。先测当前 Mdown 与基准 Typora，再设预算；无实测时不编造延迟、内存或胜负结论。
